# B3R 运行成本与部署选择

核查日期：2026-10-13（截至 20:45 UTC / 13:45 PDT）。代码依据为已接受基线 `edb19119bfced951758784b9b57741a773e5b974`（PR #67）。PR #68 的后续 UI 改动不作为已接受能力。本文件是部署与预算说明，不代表已购买云服务、已部署生产环境或已改变电脑设置。

## 1. 先说结论：BYOK 不等于运行免费

BYOK 是用户使用自己的模型服务账号或密钥，模型调用费用由该用户按供应商规则支付，**不能自动算成 B3R 的平台模型开支**。B3R 仍需承担或分配承载软件、保存数据、执行任务、联网和维护的成本。

- 只根据规则、配置或本地逻辑选择模型，不会凭空增加一次付费 LLM 调用，但仍消耗少量 CPU 等资源。
- 若将来用模型判断“该用哪个模型”、生成路由摘要或做评审，这些额外调用必须明确由谁的账号付费、是否默认启用、预算和失败回退。不能悄悄使用平台账号补足用户额度。
- 个人试用可先评估现有 Alienware；对外服务则应先确定可接受的停机、数据损失和安全隔离，再选择云端或混合方案。**保持电脑开机并不保证 24/7 可用。**

## 2. 目前系统和数据实际在哪里

仓库继承 T3 Code 的客户端—环境服务端架构：网页、桌面和手机是控制界面；模型适配器进程、终端、Git 和项目文件属于执行环境。桌面端可内置服务端，网页静态文件也可随服务端提供，并非必需购买独立前端托管。[架构依据][architecture]、[运行配置][config]

| 内容 | 当前代码所示归属 | 不应误解为 |
| --- | --- | --- |
| 任务、事件、投影和执行意图 | 服务端 SQLite；路径由配置生成，数据库名 `statev2.sqlite` | 已有云端多租户数据库或自动跨机复制 |
| 附件、浏览器产物、日志 | 服务端的 `attachments`、`browser-artifacts`、`logs` 等目录 | 已自动上传对象存储或异地备份 |
| 项目文件、worktree、终端及 agent 执行 | 实际被选中的环境 | 用户打开网页的手机会代替服务器运行任务 |
| 界面偏好 | 当前客户端；环境设置另归其服务端 | 所有设备和离线环境自动同步 |
| 凭据 | 存在环境端 `secrets` 路径及供应商特定存储机制 | 已实现统一加密 BYOK 密钥库或租户级隔离 |

事件与副作用记录采用持久化事务，后台 worker 再执行操作；“命令已接收”不等于任务已完成。[架构依据][architecture] 数据放本地也不等于不出电脑：调用远程模型时，需要的提示词、上下文、附件或代码仍可能送往所选供应商；远程访问、日志导出和备份会增加各自的数据接收方，必须分别确认。

**尚未核实：**当前实际部署地址、是否已开通任何云资源、Alienware 的系统/CPU/内存/磁盘/功耗/上行带宽，以及生产 BYOK 保存与计费方案。仓库里存在实现或文档，不代表这台电脑已经安装并启用。

## 3. 全量潜在成本清单

下面是预算检查表，不表示每项都必须购买。免费额度、已买设备和现有网络可能降低新增现金支出，但不代表没有资源消耗或维护成本。

| 项目 | 费用如何产生 | 本地与云端的区别 |
| --- | --- | --- |
| 前端、域名与入口 | 静态托管/CDN、请求量、域名续费、DNS、证书或入口服务 | 本地可同机提供前端；公开访问仍需可靠入口 |
| 后端及 worker | 常驻 CPU/内存、运行时长、排队、重试、定时任务 | 本地占电脑；云端按实例或计算量收费 |
| 浏览器和代码执行 | 浏览器会话、截图、编译测试、沙箱、临时磁盘；需要时的 GPU | 往往比转发聊天重，不能按网页访问量估容量 |
| 数据库 | 主库磁盘、读写、索引、连接、复制及托管维护 | 现有 SQLite 消耗本地/云盘；改托管数据库需适配验证 |
| 文件/对象存储 | 附件、产物、截图、版本、存取请求 | 本地磁盘也会满；对象存储属于可选扩展 |
| 备份与恢复 | 快照、异地副本、保留版本、恢复流量和演练 | 同一块盘的副本不防整机损坏或丢失 |
| 网络 | 上行/下行、云出口、跨区传输、CDN、隧道/中继或固定地址 | 本地受家庭上行、路由器及运营商条件影响 |
| 安全与可观测性 | 密钥管理、隔离、限流、防滥用、审计、日志/指标/告警保留 | 可自建但需要维护；云服务可能按量收费 |
| 账号和消息 | 身份认证、活跃用户、登录短信、事务邮件、通知 | 是否需要取决于产品登录与通知方案 |
| 开发与交付 | GitHub/CI 构建分钟、缓存和产物、测试环境、发布分发、必要的签名/商店费用 | 现有 CI 含测试和桌面构建，不是零资源操作 [CI][ci] |
| 本地长期运行 | 实测电费、额外宽带、散热、电池/风扇/SSD 损耗、设备折旧和备机 | 云端将部分硬件成本纳入账单，本地仍需人处理故障 |
| 人工和经营 | 升级、安全补丁、迁移、恢复、客服、故障响应；收费时的支付手续费、税费及合规工作 | 本地、云端都存在，个人时间也应记录 |
| 模型与其他第三方 API | 用户 BYOK 模型账单；可选平台路由调用、搜索/OCR/向量等服务 | 分开记录用户承担、平台承担、代收代付；不要重复计费 |

未引用精确价格，也未假设免费套餐适合生产。采购前应按地区、币种、计费周期、税费、额度、超额规则和服务条款查询各供应商当时的官方价格。

## 4. 三种部署方式怎么选

| 方式 | 系统与数据放哪 | 适用情形与主要代价 |
| --- | --- | --- |
| Alienware 本地常驻 | 前端/后端、SQLite、文件和 worker 都可在电脑；模型在远程供应商 | 个人、小范围试用；新增云账单可能较少，但断网、休眠、重启、个人使用争抢资源都会中断服务 |
| 云端 | 前端入口、后端和执行环境在云主机；数据在持久盘，备份另存 | 需要更稳定公开访问时；有持续账单、网络出口、安全与运维责任，不自动具备高可用 |
| 混合 | 例如云前端/入口加本地执行；或云控制面加独立本地 worker | 可保留部分本地文件或算力；需要明确任务队列、断线语义、权限和同步，拆分控制面属于待设计/验证，不能视作当前即插即用能力 |

把网页放到云端，并不会让离线的 Alienware 后端继续执行任务。若主数据在本地，云入口本身也不会自动复制数据。[远程访问依据][remote]

公开多用户服务应先验证身份、租户授权、文件及进程隔离，再讨论扩大并发。现有文档明确：项目只是组织边界，**不是文件系统沙箱**，具有相应读取权限的客户端可读取服务端账号能读取的文件。[认证边界][auth] 因此不能仅凭项目不同，就把陌生用户任务安全地混跑在存有个人文件的同一账号下。

## 5. BYOK 密钥设计：先确定执行位置

以下是设计选项，并非已实施承诺：

1. **用户自己的执行环境：**密钥由其系统或供应商客户端保存，执行发生在用户环境；B3R 尽量只存账号引用/状态。仍须明确哪些内容会交给供应商。
2. **B3R 托管执行：**若平台服务器代用户调用，就必须获得必要凭据；采用服务端加密、独立密钥管理、最小权限、租户隔离、访问审计、撤销/轮换及删除流程。解密后的密钥只在受控执行时使用，不能写入 Git、前端包、日志或普通备份。
3. **临时会话凭据：**可评估供应商支持的短期授权或仅内存保存，代价是重启/断线后可能需要重新授权；不能凭空假设供应商提供此能力。

原生供应商存在不同保存方式，例如 Antigravity 文档注明按实例文件存储，不能把所有账号都描述为“系统钥匙串加密”。[供应商边界][providers] 备份中的账号材料也属于敏感数据；备份密钥与数据应分开管理。

## 6. 先测量，再算月费与容量

平台月成本 = 固定服务费 + Σ(各资源实际用量 × 对应单价) + 本地增量电费/折旧 + 运维人工 + 明确由平台承担的第三方调用。用户 BYOK 账单另列。电费 = 墙插实测平均瓦数 ÷ 1000 × 开机小时 × 当地每度电价；不要用电源适配器额定功率直接当实际耗电。

容量至少观察三类数：
- 并发：活跃任务 × 每任务子进程/浏览器数量，叠加构建、测试和后台任务；注册人数不等于同时执行人数。
- 存储：数据库增量 + 附件/产物 + 仓库/worktree + 日志，结合每日增长、保留天数、备份副本和磁盘余量。
- 可用性：主机在线、网络可达、服务健康、供应商正常都要满足；分别记录故障与恢复时间。

建议先用本人可丢弃的测试数据测空闲、普通聊天、浏览器任务、代码构建及少量并发，记录 CPU/内存峰值、磁盘写入/增长、出站流量、排队时间、错误率、每任务运行时长和供应商实际用量，再逐步加压。没有这些数据，不承诺“一台笔记本能支持多少用户”。日志应脱敏并有保留上限。

注意：当前任务预算实现说明生产用量仍未验证，美元上限只认可合成测试价格；也不会向供应商发送剩余 token 硬上限，单轮可能超出启动时余额。因此 UI 的预算字段不能当成可靠账单封顶保证。[预算实现][budget]

## 7. Alienware 常驻前检查表

以下只供检查，不代表已修改系统：

- 确认 Windows/Linux、可用内存/磁盘及本地任务需求；源码开发要求 Node 24，不能把上游安装命令当成本仓库定制版本的部署证明。[开发说明][development]
- 验证开机自启、登录/退出后运行、崩溃拉起、更新后的重启与回滚。基线文档中 Linux 需要 systemd 用户服务及 lingering；macOS 依赖登录；**Windows 不支持现成 `t3 service` 后台服务**，若电脑是 Windows，需要单独设计并验证启动方案。[后台服务][service]
- 检查合盖、休眠、电源策略、长时间散热、断电恢复，以及路由器断电和网络重连。持续插电仍不能覆盖所有故障。
- 先采用受控远程访问和 HTTPS；认证、撤销与最小权限要通过测试。不要直接把管理端口裸露到公网；隧道和访问策略变更需另行确认。
- 做数据库一致性备份、文件备份及异机/异地保存，实测恢复。开发与生产数据目录分离，禁止让开发实例指向正在使用的生产库。[开发说明][development]
- 约定维护窗口、告警接收人、最大可接受停机，以及恢复后哪些任务只能人工重试，避免重复执行有副作用的操作。

## 8. 日常使用/上线验收、分阶段落地

**本文件的部署结论来自代码与文档只读核查。PR #67 已通过项目的 SOURCE/FIXTURE/CI 验收；这不等于下面的部署门槛通过。真实浏览器、真实供应商账号及用户电脑上的完整成功—中断—重试—恢复流程仍未验证。** 以下是拟议验收门槛；代码中有机制不等于实际环境通过，不承诺零 bug。进入日常使用前，先在隔离环境使用可丢弃项目，不能拿真实工作目录、真实付款或重要账号做破坏性测试。

| 门槛与验收标准 | 应测试的场景及留存证据 | 当前核实状态与缺口 |
| --- | --- | --- |
| 重启和断线后不丢已提交状态、不重复危险操作 | 在命令提交前后、供应商执行中、结果回写时重启；断网、供应商退出、重复提交；用事件/回执/外部副作用对账。无法确认是否执行时应显示待核查，不能盲目重放 | 架构有事务、幂等回执及 outbox；文档明确丢失供应商进程的 effect 不能简单重放。[架构][architecture] 尚无本次真实供应商端到端恢复证据 |
| 状态真实：排队/运行/供应商完成/后处理完成/人工验收分开 | 供应商结束但 checkpoint 未完、任务失败、延迟结果、人未验收；保存界面与服务端状态、时间线对照 | 架构已区分 provider turn 与 finalization；任务合约有人工 accept，代码明确 provider completion 不是 acceptance。[编排实现][orchestrator] 当前 UI 全流程尚未实测，PR #68 未作为验收通过 |
| 实验与日常工作隔离，用户和密钥不串用 | 独立数据目录、测试项目/账号；跨用户读取、错误项目、错误 provider 实例及备份访问负例；保留拒绝结果 | 开发文档要求避开 live 库；实例有账号边界，但项目不是沙箱。[开发][development]、[认证][auth]、[供应商][providers] 多租户文件/进程隔离仍需验证，不可默认安全 |
| 权限、费用、取消与关键操作确认 | 未授权读写、过期授权、重复确认、取消在执行前/中/后、额度不足；发送/删除/付款等高后果操作逐项验证确认与审计，取消后核对真实副作用 | 有任务约束/撤销/停止请求机制；停止请求不等于进程已停止，也不等于撤回已发生副作用。真实美元封顶未建立。[预算][budget] 需供应商级额度/告警和实际取消测试 |
| 固定稳定版本，可恢复升级 | 记录精确 commit、构建产物与环境依赖；从异机备份恢复；用数据库副本测试迁移、失败中断及兼容回退，核对记录与文件 | 有持久化兼容及附件历史降级风险说明。[架构][architecture]、[供应商][providers] 尚无本次备份恢复/迁移演练证据；旧程序可能无法读新数据，不能承诺直接降级 |
| 故障可见、可诊断、可响应 | 磁盘满、内存紧张、供应商 429/5xx、无网络、数据库异常；错误提示须可操作；验证脱敏、日志上限、健康检查、告警送达及响应人 | 已见日志目录与 OTLP 配置接口。[配置][config] 未核实生产采集端、告警、保留期或送达；“有日志”不等于监控值守完成 |

每项应附测试日期、版本、环境、可复现步骤、预期/实际结果及脱敏证据；失败或未测项不能标成通过。关键数据安全、授权、恢复和重复执行问题未解决前，不开放日常重要项目或公众使用；剩余低风险问题需清楚列出影响和绕行办法。

### 分阶段落地

**第一阶段：本人试用。**核实硬件/系统，完成数据目录清单、少量任务测量、备份恢复及重启验证；先不承诺公开服务可用性。

**第二阶段：受邀试用。**明确用户数和峰值任务量、每人数据上限、保留期、BYOK 执行位置、密钥生命周期、隔离边界与限流；以测量结果设并发和预算告警。

**第三阶段：对外服务。**根据允许停机时间和恢复目标选择云端/混合方案；通过权限隔离、恢复演练、故障告警与账单核对后再扩大规模。不要仅凭页面可打开就宣布生产就绪。

决策前需要回答：Alienware 的系统和配置是什么？只自己使用还是接待外部用户？愿意每月承担多少平台支出？哪些数据可以上云及保留多久？最多能接受多久停机、丢失多久的数据？平台是否承担任何路由模型费？这些答案决定部署方案，而不是“BYOK”三个字。
